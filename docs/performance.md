# 性能参考

本页记录 Jetson AGX Orin 64GB / CUDA SM87 上的实测参考，各节注明测量日期。2026-10-12 的机器为 MAXN 模式、GPU 频率 1300.5 MHz；测试未修改全局功耗或频率设置。结果对应 Rust release CLI 和匹配的优化执行包；执行库、kernel 或 ABI 变化时需重建执行包，单独更新 CPU 调度可复用原执行包。表中的 tokens/s 均按实际 token 数计算。

## 27B 分层 prefill 与批量 MTP（2026-10-17）

27B 与 Flash Next 共用分层注册、动态行调用、私有地址绑定及运行时调度。Prefill 保持原 token 块，在模型声明的层边界暂停；相邻层按剩余时间预算及实测层成本连续执行，不固定每组层数。普通 decode 的私有 GDN／attention 从原单行计算体包装成动态 1–128 请求 kernel。批量 target 验证、draft、commit、warm 和混合 prefill／verification 共用原有计算体及显式请求角色，分别绑定请求状态。

同一份官方 beam8 两级 E8P Q4A8 权重，Rust release CLI `serve` 和真实 SSE Chat API；MTP 草稿上限 4、`decode_only`、thinking 关闭、greedy、seed 20261002。固定代码任务填充至 512／2K／8K 输入，输出预算 128 tokens。下表每组重复两轮，统计完整一轮的总输出 TPS，包含排队、prefill 和生成，不等同于纯 decode TPS。“冷”表示 prefix cache 关闭；“命中”表示输入前缀完整命中，并非服务启动冷热。对照为下节 KV 预取执行包与本轮重构前的运行时。

| 场景 | 对照总 TPS | 当前总 TPS |
| --- | ---: | ---: |
| 冷 2 并发，512 + 8K | 9.07–9.21 | **9.81–9.97** |
| 冷 4 并发，2×512 + 2K + 8K | 11.37–11.76 | **14.63–15.03** |
| 冷 8 并发，2×512 + 3×2K + 3×8K | 9.78–10.07 | **11.51–11.79** |
| 全命中 4 并发，同上 4 路输入 | 32.77–33.87 | **58.91–64.67** |
| 全命中 8 并发，同上 8 路输入 | 49.21–50.09 | **69.31–90.81** |

冷 4 路最长首 token 等待由 38.17–39.87 s 降到 28.82–29.27 s，冷 8 路由 91.84–95.38 s 降到 77.59–80.51 s。8K 冷请求先到、512-token 请求晚到 200 ms 时，短请求的排队／初始化时间从 6.176 s 降到 0.022 s，首 token 等待从 6.947 s 降到 **1.616 s**。缓存命中的 8K 请求与晚到的 512-token 冷请求交错时，短请求首 token 等待为 **2.293 s**，对照 2.374 s。SSE chunk 可能包含多个 MTP token，这些 chunk 间隔不能当作单 token ITL。

16 路冷请求另测一轮 8×512 + 8×2K：总 TPS 从 21.35 变为 **20.67**，最长首 token 等待从 64.86 s 增至 **78.75 s**。该场景仍有回退和明显调度长尾；本轮没有修改既有冷请求准入限制，不能据此宣称任意并发都改善。

执行包从 173 增至 **181 个不同 cubin**，增加的是 8 个动态私有状态实现，没有枚举 batch 大小。409 个逻辑程序、5326 个局部绑定包含共享片段、逐层参数及 64 个 prefill 阶段，均不等于独立 cubin。每请求增加 2,208,512 bytes 私有临时区，全局地址表增加 917,504 bytes；没有展开权重常驻副本。

另用 `run-model` 相邻进程对照，关闭 MTP/prefix、每档预热一次后测两次单 token 输出，512／2K／8K 主干 prefill 从 678.00／689.51／618.11 变为 **678.94／689.63／617.53 TPS**，差异均在 0.15% 内。固定 64 输出的普通 decode 两次均值为 **10.74 TPS**。4 草稿 MTP 固定前缀夹具约 **24.8 TPS**，此项为强制长度的状态与性能对照，不代表自然代码生成吞吐。

普通 B2/B3/B4/B8，以及验证宽度 2/4/8 × 请求数 1/2/4/8 × 纯验证/混合 prefill 的 24 组同历史对照，最大 KL 与所选 token NLL 差异均为 0。4K 分层暂停、按预算连续执行多层、交替覆盖 workspace、取消复用及部分前缀恢复后的持久状态一致。Flash Next 重建后的执行契约与原包完全相同，真实 GPU 分层恢复检查通过。`make check` 和 `make check-offline` 通过。本轮整模型 Compute Sanitizer 因设备禁用 GPU debugging 未能执行，不能视为 memcheck 通过。

本机当前模型目录已更新到重建后的执行包，并通过完整文件校验和实际加载。从最终目录重跑的 166 个 teacher-forced 概率记录与原量化执行路径逐项相同；官方 BF16 top1 一致率保持 **98.19%**，选择全部位于 BF16 top3，高置信位置一致 **150/150**。

## 27B INT8 KV 预取（2026-10-17）

Attention 继续使用共享动态行模板。压缩 KV 与 scale 先进入 shared memory，再反量化为 FP16 tile；`cp.async` 预取下一块，与当前块的 QK／softmax／PV 重叠。源视图受每个 split 的有效结束位置限制，保护尚未提交的 KV 虚拟页。保持 INT8 KV、FP16 乘法和 FP32 累加，权重、请求状态及全局 workspace 容量不变。

离线调优同时覆盖短行、尾部和不同 KV 长度，主干 prefill 发布的 attention 配置由 7 种减为 5 种。大行数胜出配置为 query tile 64、KV tile 64、256 threads、一级压缩预取；短行数也从同一个模板选择配置。没有增加按上下文长度选择 kernel 的表；E8P 投影仍为每种几何一个动态 fallback 及精确 AOT。

同一份官方 beam8 两级 E8P Q4A8 权重，普通 Rust release CLI、关闭 MTP/prefix cache、`decode_only`。每个长度预热一次，再测两次一 token 输出；prefill 只计主干，输出头另计。对照为单一动态投影 fallback 的已验收执行包。

| 输入 tokens | 对照 TPS | KV 预取 TPS | 变化 |
| --- | ---: | ---: | ---: |
| 512 | 686.89 | **684.36** | −0.4% |
| 2048 | 684.96 | **689.55** | +0.7% |
| 4096 | 653.26 | **659.14** | +0.9% |
| 8192 | 581.00 | **617.72** | +6.3% |

13 个长度点中，129/257-token 请求分别下降约 1.1%/1.0%，其他短尾下降不超过 0.7%。长上下文仍承担更多 attention 计算，512-token prefill 也仍未达到 800 TPS。

NCU 采样真实 8K 上下文、4096 行 query 的第 3 层 attention：时延从 127.80 降至 **80.50 ms**（−37.0%），Tensor Core 活跃率从 11.51% 增至 18.28%；PC 采样中 long-scoreboard 状态占比从 41.96% 降至 2.61%。L2 命中率为 93.53%／93.27%，两者均无 local-memory spill。新 kernel 出现异步 LDGSTS，测量支持预取减少全局访存依赖等待这一方向；采样状态占比不等同于精确周期占比。

逐算子 stream-event 诊断中，8K 最后一个 4096-token 分块的 16 层 attention 合计从 2.094 降至 1.290 s，该分块总计从 7.836 降至 7.021 s。此项为带事件插桩的成本分解，吞吐仍以上述普通 CLI 完整请求为准。

官方 BF16 的 166 个固定历史概率检查保持 top1 一致率 **98.19%**，选择全部位于 BF16 top3，高置信位置一致 150/150。与此前量化执行包相比，166 处 greedy 选择全部不变，161 处概率记录逐项相同，目标 token NLL 差绝对值最大 0.00226。普通 CLI 的固定 64-token 请求，decode 为 **10.75 TPS**，对照约 10.76 TPS。

另以此前量化执行包为数值参考，在 4K／8K／16K 固定历史上导出 24 处完整词表 logits：最大 KL **0.01018**，平均 KL 0.00177，目标 NLL 差绝对值最大 **0.06460**，top1 一致 24/24。符合现有执行重组门限 KL<0.05、NLL 差绝对值<0.1；此项不替代 BF16 量化质量评估。固定 64-token 强制延长夹具重复三次，输出和全部 167 项状态哈希一致；相对旧包的生成差异发生在真实 EOS 之后，实际回答相同。

新预取实现通过 16 个算子场景的数值、非对齐尾部、空上下文和改输入 Graph replay 检查。禁用 Torch allocator cache、只分配有效 KV 后，Compute Sanitizer memcheck 为零错误。

B2/B3/B4/B8 同历史 KL 和目标 NLL 差均为 0；取消、槽位复用、冷混合 prefill、MTP 缓存重放、32/4093-token 部分前缀恢复及 4 草稿 MTP 检查通过。固定强制延长夹具的 4 草稿 MTP 两次测量均值为 24.39 TPS，对照为 24.43 TPS（−0.2%）；这不是自然代码生成吞吐。

`make check`、`make check-offline`、Python lint/format 及模型计划验证通过；本机当前模型目录已更新到重建后的执行包。

## 27B 单一动态投影 fallback（2026-10-17）

当前主干 336 个 E8P 投影分为 6 种矩阵几何，每种几何、输出 dtype/stride 和压缩布局只发布一个动态 cubin。常用 1/2/3/4/8/16/32 行保留同源 AOT；其他行数传入同一个动态入口。取消投影的长度区间选择表，kernel 内保留必要的有效行和尾块处理。离线调优汇总多个长度的总 GPU 时延选择一个配置，候选不作为线上路径发布。

执行包仍有 208 个程序，不同 cubin 从 188 降至 **170**，局部绑定从 8974 降至 **5102**。正式构建器直接发布单一 fallback，已删除按长度合并投影选择表的工具；构建契约测试及实际执行包检查均验证一个动态入口和 7 个精确 AOT 行数。

同一份官方 beam8 两级 E8P Q4A8 权重、相同输入 token ID，普通 Rust release CLI、关闭 MTP/prefix cache、`decode_only` Graph。每个长度预热一次后测两次一 token 输出请求；prefill 只计主干，输出头另计，吞吐按总 tokens 除以总 prefill 时间计算。

## Flash Next 配置

使用官方 checkpoint 构建的文本模型：自有整数 E8P Q2A8 专家、Q4A8 输入投影与输出头、W8 输出投影与共享 FFN，精度敏感路径保留 BF16/FP16/FP32。专家全量常驻，KV 为 group-64 INT8，GDN 持续状态为 FP32。测试不含图片、其他并发请求或历史续写草稿。

```bash
./target/release/orinfer serve /path/to/optimized-flash-next \
  --model qwen-flash-next --cuda-graph decode_only \
  --resident-experts full --mtp-drafts 3 \
  --prefix-cache-mib 1024 --memory-reserve-mib 512
```

关闭 MTP 的对照使用相同执行包和配置，只将 `--mtp-drafts` 改为 `0`。草稿长度使用正常的请求级自适应策略，没有固定验证宽度。

请求参数为 `enable_thinking=true`、`reasoning_effort=medium`、`temperature=0`、`seed=20261002`、`thinking_token_budget=16384`、`max_completion_tokens=16384`。思考和代码共享 16K 总输出上限；API 为思考结束标记和至少一个答案 token 预留空间。

场景要求从零实现安全 Rust 流式帧解码器：大端 u32 长度头、任意碎片输入、最大帧限制、复位和标准库单元测试。提示包含与实现无关的仓库参考 helper，以构造不同输入长度。完整请求测试的输入分别为 512、2048、8191 tokens；下方独立 prefill 测试使用严格的 512、2048、8192-token 输入。

## 连续片段与 prefill autotune

Flash Next 最终包的混合 prefill 片段与 MTP warm 都支持连续 1–512 行，普通 prefill 仍为 1–4096 行。warm 从 11 个长度包装收敛为一个动态程序及输出头；混合调度不再凑 16／128／512。片段角色通过 ABI v1 flags 显式传递前置 prefill 片段数，2 行 prefill 与 2 行验证不再靠长度区分，角色边界参与计划和 Graph 缓存身份。

最终执行包为 525 个编译定义、388 个不同 cubin，比上一包增加两个按真实行数复制 warm 输入的 kernel。包重打为一个资产 safetensors，目录共七个文件，未引用的旧资产不保留。2739 个不可变权重／数据 buffer 与上一包逐项一致，resident／capacity bytes 仍为 41,961,044,464／49,605,600,400；schema 与 C ABI 继续为版本 1。

## MTP 验证复用 packet

模型声明支持 batch 验证时，单请求也使用 Verification packet，复用动态行计算、请求状态绑定和完整 Graph。共享片段与完整 packet 使用同一套分支捕获：只启用片段完整覆盖的 fork/join；连续辅助 kernel 归属其原始槽位，重复私有状态槽位不影响无关共享分支。节点优先级使用实际 launch grid。

HC injection 的窄行实现通过复制未使用的 MMA 行／列消除循环内条件加载，并按对齐的 BF16 对读取共享内存，保留原 K16 累加顺序。1–4 行的单算子耗时从约 26 μs 降至 19 μs；98 份真实矩阵、838 个矩阵／长度组合与原矩阵实现逐位一致。FP16／BF16、单输出门控、非对齐尾部和修改输入／权重后的 Graph 回放检查通过。离线选优仍只发布 tiny1、bulk16，未选中的实现不进入执行包。
