# Engineering conventions

[简体中文](../../AGENTS.md) | **English**

These instructions apply to the entire repository. Explicit user instructions take precedence.

## Scope

- Target hardware is the local **Jetson AGX Orin 64GB, aarch64 / CUDA SM87**.
- Supported model families: Qwen3.8-27B and Qwen3.5-4B (`Qwen3_5`), Qwen3.8-Flash-Next (`qwen4_exp`), and Index-Translate-2B/9B (`Qwen3_5`). Text, single-image, and ordered multi-image inputs are in scope; video is not.
- Use Rust for online runtime and serving. Production GPU kernels originate in TileLang; Python is for offline conversion, compilation, references, and validation only.
- Keep model implementations, shared execution components, TileLang kernels, and offline tools in one workspace. Do not split repositories by model × precision. `orinfer-models` independently registers model adapters and compute policies. Deployment Rust `cdylib` packages use a versioned C ABI to generate programs, dynamic batches, and state bindings, shipping matching TileLang cubins. The generic CUDA executor must not hard-code model families, layers, dimensions, or layer order; new architectures must not add core dispatch enums.
- Prefix caching and multi-request batching are first-class features. Every cache restoration or scheduling change must preserve **all** KV/GDN/convolution/MTP state and request isolation.
- License: LGPL-3.0-or-later. Preserve third-party notices and license conditions.

## Implementation contracts

### Model fidelity, precision, and memory

- Verify GDN, GQA, RoPE, zero-centered RMSNorm, embedding, and output-head semantics against real checkpoint configuration.
- Recurrent GDN state is FP32. KV, convolution, GDN, positions, and other causal state belong to each request.
- Index-Translate-2B/9B reuse 27B dynamic GDN/GQA, FFN, vision, MTP, and request-state components with configuration-derived dimensions/head counts; do not clone their execution flow. Backbone, embedding/output head, and large vision matrices use two-stage E8P Q4A8; sensitive output/MTP projections use W8. The 2B tied embedding/head use one K128 compressed bank; 9B keeps separate banks according to the official configuration. Decode and inverse-rotate selected embedding rows on demand, rotate A8 input for the output head, and do not duplicate or permanently expand large weights.
- Qwen3.5-4B uses 2,560 hidden, 9,216 FFN, 32 layers, 32 GDN value heads, and 16/4 GQA heads. Tied embedding/output head shares one E8P Q4 bank. When the original checkpoint omits `generation_config.json`, pin EOS/padding from model configuration and tokenizer while preserving explicitly supplied generation-config bytes.
- When changing prefill/decode, restore, or branching, validate **every** state component, not merely KV.
- KV-growth lists can include both request-private KV and context-growing shared workspaces. Resolve private mappings by owner, shared mappings by session; never assume everything in a growth list belongs to the request arena.
- Keep one resident compressed W4 representation; count scales, zeros, LUTs, padding, and persistent duplicate representations in average bits per weight. Temporary W8 is not a permanent weight cache.
- Flash Next uses Q2A8 plus quality-oriented mixed precision. QSA long-context KV is group-64 symmetric INT8 with FP16 scales. Compressed indices and pending blocks are request-private. Default expert residency is full; `--resident-experts N` uses declared expert banks and routing counts to page from SSD into CUDA VMM with a shared global SLRU. Limited residency disables CUDA Graph for now; MTP experts stay fully resident. Routed extra experts and page granularity mean the setting is not a strict byte ceiling. Do not cache expanded W8 weights. HC keeps BF16 weights. PLE lookup uses a bounded CPU cache; n-gram and convolution histories participate in request state and prefix restoration.
- Current 27B experiments/deployment use **beam-8-reencoded, two-stage E8P Q4A8** (`coefficients=[4,1]`). Local paths: `artifacts/models/qwen3.8-27b-e8p-q4a8-current` and `artifacts/quantization/qwen35-e8p-beam8-20261016/converted`. Old quantization/TCQ experiments remain records, not fallback weights. A change in weight values with unchanged layout/buffer contracts may reuse a compatible execution package but still requires quality, state, and real-request performance acceptance.
- For each Qwen3_5 integer projection geometry, dtype/stride, and compressed layout, publish **one dynamic prefill fallback**. Common 1/2/3/4/8/16/32 rows may retain source-identical AOT variants; non-AOT packet sizes up to 128 may choose bounded dynamic variants offline, passing true row counts and excluding exact AOT points. Select dynamic fallback from aggregate measured costs across lengths, not a table of per-prefill-length cubins. Candidate kernels are not multiple runtime paths. Inspect the published package, test tails, complete request performance, and all state.
- 27B prefill pauses at model-declared layer boundaries with the original dynamic row block. Only Hidden and FP32 residual live across layers in shared workspace; state growth/commit use common Frame logic. Ordinary decode wraps one-row TileLang GDN/attention compute in address tables for 1–128 independent requests. Ordinary/verification/mixed packets share target pre/post work. `MixedRows` carries explicit role boundaries: ordinary requests output the last position, verification outputs every position. Draft/commit/warm use shared MTP workflows with owner-bound draft conditioning, compact GDN factors, convolution, KV, and hidden rings. Reuse Flash Next's generic packet invocation, address binding, and layer-prefill registration without copying its HC/PLE/QSA or fixed layer geometry.
- Flash Next's selected quantization is custom integer E8P Q2A8 for experts; signed-block128 rotated, per-output-row-scale Q4A8 for GDN QKV/Z, QSA Q/gate, and shared target/MTP head; W8 for GDN/QSA output, shared FFN, and MTP draft Q/O; other sensitive paths retain their prescribed mixed precision. The native adapter validates this policy. Do not retain experimental per-matrix precision branches.
- Flash Next uses **our own** integer E8P and rotated compression, dequantizing to INT8 computation; it does not reuse community Q2 encodings. Prioritize real kernels and end-to-end inference; uncalibrated or limited calibration is acceptable when labeled. Stream original pinned BF16 matrix-by-matrix or expert-by-expert; a full BF16 local copy is unnecessary. Full calibration needs separate expert-coverage/layer-error validation. Do not call dequantized community Q2 an original BF16 reference.
- E8P may losslessly repack K64/K128 compressed weights and use complete A8 bit planes with two INT4 Tensor Core products to recover the original INT32 result. **This is not A4 quantization.** Preserve original scales and FP16 boundaries; validate the nonzero-codebook premise. Unverified MTP, concurrent, or large-prefill paths retain INT8 compute reading the same compressed bank.

### Model data, ABI, and runtime boundaries

- Online models use the HF config/tokenizer directory plus `cache/model.json`. Standard safetensors shards retain the current compressed representation. Startup checks dtype/shape/physical layout/container bounds; enable payload hashes explicitly through `--verify-weights`, while `validate-model` always checks all content. Configuration signatures, frontend assets, CPU metadata, native library, and kernel identities remain hash-verified. The `execution_package` digest pins standalone native execution logic. Phase one is INT8-centered, quality-prioritized mixed precision with FP16/FP32 exceptions; do not implement `force_int8` or arbitrary model-format imports.
- Offline AOT manifests are build intermediates, not deployable models. Online data and execution packages remain **schema 1**, supporting only current native package structure. Do not add legacy-package or schema-2 compatibility branches; operator fixtures have their own format.
- Keep service protocol in `orinfer-api` and CLI argument/command handling in `orinfer-cli`. Separate generic CUDA execution, loading, model adapters, compute policies, generation, vision, and MTP control. Track weight, sequence state, and workspace by lifetime/scope.
- JSONL batch shares HTTP Chat frontend, model loading, and continuous GPU worker; do not clone inference or state-commit logic. Preprocess input within budgets, persist results on completion, and validate input/model/request-default identities on resume. Count truncations separately from errors.
- `serve` defaults to `latency` scheduling; `batch` defaults to `throughput`. Throughput mode reuses dynamic packets/native prefill but removes online admission time gates, the two-long-prefill restriction, and mandatory decode time quotas. Memory, isolation, and output budgets still apply; choose joint paths using measured cost. Sorting must use a **frozen elapsed-time snapshot**, not call a changing clock inside comparators.
- Global JSONL planning extracts actual token prefixes with the Chat frontend. Its index/workspace budget is at most one-quarter of preprocessing memory and at most 4,096 prefix tokens per record. Unplannable or over-budget inputs retain streaming processing. Reordering preserves physical line numbers, `custom_id`, input identity, and resume semantics. Cache hints affect snapshot selection only, never input/output truncation. Learn output-length estimates only from naturally completed requests; max output budget is not an observed length. Async result queues count toward memory and must drain/sync before reporting success or interruption. Propagate write errors.
- Upload host input through bounded, append-only pinned slabs in stream order. Chunk large input too; do not fall back to full-context synchronization above one slab. The caller may release its buffer after upload returns, so slab reuse and cleanup must wait for DMA. Confirm GPU completion before returning readback.
- Merge HF `tokenizer_config.json` added-token definitions into the deployed `tokenizer.json` and verify IDs individually. Acceptance compares **actual Transformers-generated token IDs**, not merely rendered strings. Do not silently tokenize missing thinking/tool markers as plain text.
- Catalogs store shared compiled definitions/assets and dynamic launch templates only. Compile per-layer tensor roles/arguments into a Rust model library using shared call templates, layer argument tables, and deduplicated specialization selectors; never copy the entire specialization binding set per layer. Export generated plans through owner-managed C arrays in `orinfer_model_plans_v1`. Online code does not parse expanded `kernels` lists or Python plans. Catalog identity must match the native binding registry; verify full program/arguments/state after rebuild. `plan-model` retains the build contract for offline use; online creation exposes only final programs, local specializations, and expert-residency bindings, not unfused build inputs.
- Rust binds actual host ABI argument order, grid/block/shared memory and checks CUDA status, unsafe boundaries, resource lifetimes, and stream ordering.

### Dynamic compute, Graph, and causal state

- Flash Next ordinary decode (1–128 requests), mixed batching, and MTP target verification share a **1–1024-row** target template. Single-/multi-stream draft and warm share a **1–512-row** draft template, with a shared output-head implementation. Handle causal segments, accepted-prefix factors, Graph capture, commit, and request isolation separately without duplicating projection/HC/FFN/expert compute.
- Integer projections and experts specialize 1/2/3/4/8/16/32 rows offline; others use dynamic-argument cubins. TileLang tuning may change only legal tiles preserving scale, dtype, and reduction boundaries, with consistent routing/expert tiles. Runtime consumes offline-generated row selection tables, including for single-stream execution. Auxiliary kernels must not retain arbitrary 8/16 cutoffs. Never restore old per-capacity online batch planners, padded dummy rows, or separate mixed-decoder subgroup fallbacks. Intermediate offline bindings only build final templates. MTP short tails use one-row packets; single-target programs are retained only for state preparation/reference.
- Graph branches register by template slot. Reuse after validating read/write dependencies for every specialization; do not hand-code batch tiers or tune online. Invalidate build caches when source, compiler, or device identity changes. Graphs require stable addresses and preallocated workspaces; verify replay with changed inputs.
- Shared segments and complete packets use the same Graph-branch capture infrastructure. Enable fragments only for complete unambiguous fork/join regions. Contiguous auxiliary kernels expanded from dynamic slots belong to one boundary. Duplicate private-state slots must not incorrectly close unrelated shared branches; prioritize according to actual launch grids. If batch verification is declared, single-request MTP must use the same Verification packet, not a separate per-operator chain.
- Flash Next causal segment and MTP state control use dynamic-length kernels: target/draft segments up to 512 rows; verification and accepted-prefix restore up to eight rows. Pass real lengths at runtime, never infer them from program names. Head-major GDN-factor stride follows real rows. Convolution/PLE histories and hidden rings follow published buffer geometry. Aliases and scheduling chunks do not imply distinct cubins. Do not restore per-length state-kernel enumerations. Preserve owner/state views through verification, restore, and capture.
- Publish Flash Next only after native `build.py` plus shared `row_selection.py` offline tuning; release selected local variants only. Mixed causal and MTP warm accept continuous lengths 1–512—do not artificially split at 16/128/512; actual segments depend on remaining work and latency budget. `MixedRows` ABI-v1 flags explicitly encode preceding prefill fragments; do not infer roles from row counts. Graph/cache identities include those role boundaries.
- Warm uses a single capacity template with `min_tokens=1`. Update `MtpLength` before mapping dynamic KV. Repackage final assets without unused candidates or stale cubins. Measure shared large-row compute with `row_tuning.py` and `converge_kernels.py`, never retain manual 32/128 performance cutoffs; select expert route/up/down jointly.
- HC injection direct/matrix tiles must preserve BF16 MMA K16 accumulation order even in single-row reference implementations. Parallel FP32 summation is not a numerically identical alternative. Merged dynamic bindings must preserve original grids, argument expressions, and token-to-expert-row multipliers; identity-only changes must not alter execution semantics.
- Pass actual verification length before mapping MTP KV. Vision uses one dynamic patch template; merger launch size follows actual patch count divided by four. Expanding vision capacity must not silently expand text program row contracts. MTP verification, restore, and capture each use one entry point of capacity eight, `min_tokens=2`, with actual length passed at runtime. Fixed-shape references are offline inputs only.
- Cooperative launches must declare and validate occupancy; ordinary CUDA launches do not permit implicit inter-block synchronization.
- Evaluate performance on complete real-model request paths. Synthetic probes, extrapolated microbenchmarks, and four-output profiles are **not** full-request TPS evidence.
- Compare quality against official BF16 or same-model FP8 with fixed seed 20261002 and teacher-forced histories. Different selected tokens alone are not automatic failures; evaluate task outcomes, target NLL, and long-context behavior separately.

## Development workflow

- Use `rg` to inspect callers and dependencies before changes. Prefer changes that are small but complete; do not automatically spawn subagents.
- Manage CPU Python dependencies in a pinned project `.venv` via `uv` and `make python-env`; do not modify host Python. `make check` runs Rust formatting/build/Clippy/tests and CPU evaluation. Run GPU validation through `bash tools/operators/run.sh` using the pinned compiler image.
- Serialize GPU experiments with `artifacts/gpu-experiment.lock`. Preserve unrelated services; never adjust global frequencies/power or clear caches without an explicit request.
- Run GPU tests using test binaries from the **current** build, verifying that the test actually executed. Never hard-code/reuse old `target/deps` test executables.
- Rebuild native Flash Next integer kernels via `tools/model/flash_next/build.py`: derive construction contracts from weight geometry/host ABI, tune real weights, atomically cache content-verified compiled items, and publish only after Rust plan validation. Input must provide a pinned execution contract; this is not a raw-weight importer. Retain verified HC/QSA/state and joint expert selectors while separately checking real expert geometry. Do not chain historical upgrade scripts as a production rebuild.
- HC lossless exponents and QSA radix shifts are mutable **ABI scalars** using shared cubins. Private state wrappers must preserve scalar values, column stride, and byte offsets. Tune QSA stripe count offline. Dynamic integer projections must test multiple real row lengths and capacity limits, not only one short row count. Merge adjacent selection ranges only for completely identical arguments and launches; do not bridge gaps or silently change expert route tiles.
- Verify new kernels numerically, across unaligned tails, and with actual changed-input Graph replay. State changes also need chunking, restore, and isolation tests.
- Compose projection kernels from weight loading, compute schedule, and output processing. W8/Q4/fused SwiGLU reuse `integer_core`; BF16 matrices reuse `floating_core`; E8P bit planes, dual INT4 products, and output reuse `e8p_core`. These are compile-time components: do not clone compute loops by model, prefill/decode, or MTP. Preserve memory schedules, floating reduction order, and rounding semantics. Two-stage 27B E8P Q4A8 also reuses `e8p_core`, with INT4 and INT8 fallbacks reading the same K128 compressed bank. Include inlined component source identity in tuning-cache keys.
- Flash Next adapters accept only current dynamic prefill/target/draft templates and causal-state contracts. Do not revive fixed-capacity plan registration/fallback/per-length rewrites. Q4 input transforms must be tied to consumers by section, activation/scale workspaces, and symbol tables. Shared QKV/Z transforms run before the first consumer and are emitted for each program alias; dependency modeling must not be replaced by patches to operator indices.
- Keep implementation, necessary build tools, tests, examples, and user documentation in the repository. Do **not** commit research logs, agent-delivery records, historic experiment reports, or local environment evidence.
- Keep weights, binaries, cubins, caches, logs, and traces in ignored `artifacts/` and `target/` directories. Never commit secrets or tokens.
- Deploy with Rust `orinfer package install`; Python and online compilation are not required. New engine, execution, and source release archives use `.tar.xz`; installers still accept released `.tar.gz`. Python remains for offline builds, archive generation, and release checks only.
